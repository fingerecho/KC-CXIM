# 三、硬约束（违反任意一条，代码直接作废）

## R1 依赖约束

- 框架只用 **Drogon 1.9.x**。
- 业务 JSON 只用 **nlohmann/json**。
- 禁止引入其他网络库或 JSON 库，例如：
  - 禁止 Crow、oatpp、cpp-httplib、Pistache、Boost.Beast、userver
  - 禁止 RapidJSON、jsoncpp 业务用法、Boost.JSON、simdjson
- Drogon 内部配置解析使用 jsoncpp 属于框架内部行为，允许；
  但业务代码禁止出现 `Json::Value`、`getJsonObject()`、`newHttpJsonResponse()`。
- 允许使用 OpenSSL（Drogon 已依赖）实现 HMAC-SHA256 / PBKDF2；
  不得引入 jwt-cpp、bcrypt、libsodium 等新库。

## R2 目录分层约束

必须包含并使用以下目录：

```text
controllers/   路由注册与参数解析
services/      业务校验与流程编排
repositories/  数据库访问（只允许使用 Drogon 自带 dbClient）
filters/       请求拦截器 / advice
```

硬性规则：

- 禁止在 controller 或 handler 中直接拼 SQL、调用 `execSqlAsync`。
- 所有 SQL 只能出现在 `repositories/`。
- service 不得直接返回 Drogon 的 HTTP 响应，不得操作 `HttpResponse`。
- controller 不得做业务规则校验（如状态枚举、分页范围、账号状态），只能做：
  - 路由与 HTTP 方法
  - 路径参数 / 查询参数 / JSON 体的类型解析
  - 调用 service、把结果交给 `Responder`

## R3 异步约束

- 所有 handler 必须是异步写法。
- 本骨架**统一采用回调式异步**：
  - `HttpCallback` + Drogon `DbClient::execSqlAsync`
  - **禁止**混用 Drogon 协程。
- handler 内禁止任何同步阻塞调用，包括但不限于：
  - `execSqlSync`
  - `sleep` / `usleep` / `Sleep`
  - 同步文件 IO（`std::ifstream`、`std::ofstream`、`fopen` 等）
  - 同步 HTTP / socket 调用
- 启动阶段读取配置、初始化日志允许同步；运行期 handler 内不允许。

## R4 异常约束

- 每个 handler 外层必须有 `try/catch`。
- 每个异步回调内部也必须 `try/catch`。
- 异常一律转换为统一 JSON 错误，不允许异常逃逸到 Drogon 框架。
- 捕获顺序：
  ```cpp
  catch (const AppError& e)      -> 返回 e 对应状态码与统一错误
  catch (const std::exception& e) -> 记录日志，返回 500 统一通用错误
  catch (...)                    -> 记录日志，返回 500 统一通用错误
  ```

## R5 异步回调纪律

- 回调必须**恰好调用一次**，成功或失败二选一，绝不允许：
  - 成功回调后又调用异常回调
  - 两个并发查询各自触发一次响应
  - 超时/失败后再次回调
- 捕获变量时**禁止**：
  - `[&]`
  - 裸 `[this]`
- 需要延长生命周期时：
  - service / repository 继承 `std::enable_shared_from_this<T>`，捕获 `auto self = shared_from_this();`
  - controller / handler 不捕获 `this`，改为捕获 `std::shared_ptr<Responder>` 与按值参数
- 推荐使用 `Responder`（见第十四章）作为“只响应一次”的守卫。

## R6 统一错误格式

错误响应体必须**恰好**是三个字段：

```json
{"code":"...","field":"...","message":"..."}
```

- 入参错误：HTTP 400
- 资源未找到：HTTP 404
- 内部错误：HTTP 500，且不得泄露 SQL、堆栈、异常原文、表名、文件路径
- 允许并要求使用：401 未认证、403 无权限、409 冲突、501 未实现
- 错误必须使用正确 HTTP 状态码，禁止 HTTP 200 包错误

# 七、异步与生命周期规范（核心）

## 7.1 统一回调式异步

handler 签名统一为：

```cpp
void xxx(const drogon::HttpRequestPtr &req,
         std::function<void(const drogon::HttpResponsePtr &)> &&callback);
```

数据库统一为：

```cpp
db->execSqlAsync(sql,
    [/* 按值捕获 */](const drogon::orm::Result &result) { /* 成功 */ },
    [/* 按值捕获 */](const drogon::orm::DrogonDbException &e) { /* 失败 */ },
    param1, param2, ...);
```

## 7.2 响应只发一次

统一使用 `Responder`：

```cpp
class Responder final {
public:
    using Callback = std::function<void(const drogon::HttpResponsePtr &)>;
    explicit Responder(Callback cb) : cb_(std::move(cb)) {}

    void ok(nlohmann::json data, std::string requestId = {}) {
        if (done_.exchange(true)) return;
        cb_(makeSuccess(std::move(data), std::move(requestId)));
    }

    void fail(const AppError &e) {
        if (done_.exchange(true)) return;
        cb_(makeError(e));
    }

    void failUnknown(const std::exception &e) {
        if (done_.exchange(true)) return;
        LOG_ERROR << "unhandled exception: " << e.what();
        cb_(makeError(AppError::internal()));
    }

    void failUnknown() {
        if (done_.exchange(true)) return;
        LOG_ERROR << "unhandled unknown exception";
        cb_(makeError(AppError::internal()));
    }

private:
    std::atomic_bool done_{false};
    Callback cb_;
};
```

要求：

- 控制器中不捕获 `this`。
- 捕获 `std::shared_ptr<Responder>`，按值拷贝到异步回调。
- 所有异步回调内部 `try/catch`，失败调用 `responder->fail(...)`。
- 即使重复调用 `ok/fail`，`Responder` 也只发送一次。

## 7.3 service / repository 生命周期

service / repository 继承：

```cpp
class UserService : public std::enable_shared_from_this<UserService> {
public:
    void listUsers(..., Callback cb) {
        auto self = shared_from_this();
        repo_->query(..., [self, cb = std::move(cb)](Result r) mutable {
            cb(std::move(r));
        });
    }
};
```

禁止：

```cpp
[&] { ... }          // 禁止
[this] { ... }       // 禁止
[=] { this->x(); }   // 禁止（隐式 this）
```

## 7.4 多异步汇合时的 exactly-once

当 count + list 两个查询都需要完成才响应时，使用共享状态：

```cpp
struct PageState {
    std::atomic_int remaining{2};
    std::atomic_bool done{false};
    std::uint64_t total{0};
    std::vector<UserSummary> rows;
    std::function<void(std::variant<UserPage, AppError>)> cb;
};
```

规则：

- `remaining.fetch_sub(1) != 1` 时直接返回。
- 最后一次完成时再次检查 `done.exchange(true)`。
- 任一查询失败，先 `done.exchange(true)` 再回调错误，另一个查询的回调被丢弃。
- 共享状态用 `std::shared_ptr` 管理，禁止裸指针。
- 若担心可见性，用 `std::mutex` 保护 `total/rows`，或用默认 `seq_cst` 原子操作保证 happens-before。

# 八、统一响应与错误

## 8.1 成功响应

HTTP 200：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "..."
}
```

说明：

- 成功 `code` 使用数字 `0`，与现有前端 `request.ts` 的 `typeof body.code === 'number' && body.code !== 0` 兼容。
- 错误绝不使用 HTTP 200。

## 8.2 错误响应

错误体必须恰好三个字段，不要额外加 `data`、`request_id`、`stack`：

```json
{"code":"INVALID_PARAM","field":"page","message":"页码必须大于 0"}
```

推荐错误码：

| HTTP | code | 场景 | field |
| --- | --- | --- | --- |
| 400 | `INVALID_PARAM` | 参数缺失/类型错误/枚举非法 | 字段名 |
| 400 | `INVALID_BODY` | JSON 解析失败 | 空字符串 |
| 401 | `UNAUTHORIZED` | 未带 token / token 非法 | 空字符串 |
| 401 | `TOKEN_EXPIRED` | token 过期 | 空字符串 |
| 401 | `INVALID_CREDENTIALS` | 账号或密码错误 | `password` |
| 403 | `FORBIDDEN` | 角色权限不足 | 空字符串 |
| 404 | `NOT_FOUND` | 用户/资源不存在 | `id` |
| 409 | `CONFLICT` | 状态冲突 | 字段名 |
| 500 | `INTERNAL_ERROR` | 未预期异常 / 数据库失败 | 空字符串 |
| 501 | `NOT_IMPLEMENTED` | 依赖后端能力未就绪 | 空字符串 |

500 的 `message` 固定为：

```text
服务器内部错误，请稍后重试
```

严禁在 500 响应中返回：

- SQL 语句
- 数据库错误原文
- 异常 `what()`
- 堆栈
- 文件路径
- 表名 / 字段名

详细信息只写服务器日志，并带 `request_id`。

# 九、过滤器与拦截器

## 9.1 RequestId

- 在 pre-routing advice 中生成 UUID：
  `drogon::utils::getUuid()`
- 写入 `req->attributes()->insert("request_id", uuid)`
- 在 pre-sending advice 中写入响应头：
  `X-Request-Id: <uuid>`
- 日志、审计统一使用该 id。

## 9.2 CORS

- 允许来源从配置读取，默认 `http://localhost:5173`。
- 允许方法：`GET, POST, PATCH, PUT, DELETE, OPTIONS`。
- 允许头：`Authorization, Content-Type, X-Request-Id`。
- 暴露头：`X-Request-Id`。
- `OPTIONS` 预检直接返回 `204 No Content`，不进入业务。
- CORS 响应头通过 pre-sending advice 统一添加。

## 9.3 AuthFilter

- 读取 `Authorization: Bearer <token>`。
- 校验 HS256 签名、`iss`、`exp`。
- 校验通过后把以下内容写入 request attributes：
  - `admin_id`
  - `admin_username`
  - `admin_role`
- 失败返回 401 统一错误，**不调用** `fccb()`。
- 成功调用 `fccb()`。
- 只做 CPU 计算，不查库、不阻塞。
- filter 内部也必须 `try/catch`。

## 9.4 RbacFilter

- 从 attributes 读取 `admin_role`。
- 按请求路径/方法做角色白名单校验。

# 十二、认证、安全与审计

## 12.1 密码

- 使用 PBKDF2-HMAC-SHA256（OpenSSL），迭代次数 ≥ 120000。
- 盐使用 `RAND_bytes` 生成，至少 16 字节。
- 存储格式：
  `pbkdf2-sha256$<iterations>$<salt_base64>$<hash_base64>`
- 比较使用常量时间比较（`CRYPTO_memcmp`）。
- 禁止在日志、响应、审计中输出明文密码或哈希。
- 生产环境建议替换为 Argon2/bcrypt，但本骨架禁止为此引入新库；
  在 README 中标注 TODO。

## 12.2 JWT

- HS256。
- Claims 至少包含：
  - `sub`：admin id
  - `username`
  - `role`
  - `iss`
  - `iat`
  - `exp`
  - `jti`
- 使用 OpenSSL HMAC-SHA256 + base64url，不引入 JWT 库。
- 校验时使用常量时间比较签名，并校验 `iss`、`exp`。
- Access token 默认 900 秒；Refresh token 默认 7 天。
- Refresh token 使用 `RAND_bytes` 生成 32 字节随机值，
  数据库只存 SHA-256 哈希。
- 刷新时旋转 refresh token，旧的标记 revoked。

## 12.3 审计

- 所有写操作（封禁、解禁、重置密码、配置变更等）必须写 `audit_logs`。
- 审计写入异步执行，失败只记录日志，不影响主流程响应。
- 审计内容不得包含密码、token、消息正文等敏感信息。
- 审计操作必须带 `request_id`、管理员 id、IP、User-Agent。

## 12.4 输入与输出安全

- JSON 解析使用 `nlohmann::json::parse` 并捕获 `parse_error`。
- 禁止使用 `req->getJsonObject()`（jsoncpp）。
- 禁止使用 `newHttpJsonResponse()`（jsoncpp）。
- 响应体统一：
  ```cpp
  auto resp = drogon::HttpResponse::newHttpResponse();
  resp->setStatusCode(status);
  resp->setContentTypeCode(drogon::CT_APPLICATION_JSON);
  resp->setBody(body.dump());
  ```
- 响应头建议：
  - `X-Content-Type-Options: nosniff`
  - `X-Frame-Options: DENY`
  - `Referrer-Policy: no-referrer`
- 敏感字段（手机号、邮箱）返回前脱敏。

# 十三、日志与可观测

- 使用 Drogon `LOG_INFO` / `LOG_WARN` / `LOG_ERROR`。
- 每条关键日志带 `request_id`。
- 记录：
  - 启动配置摘要（不含密钥）
  - 数据库异常（服务端日志，不返回客户端）
  - 登录失败次数（按用户名/IP，避免记录密码）
  - 审计写入失败
- 禁止：
  - `std::cout` / `printf` 作为业务日志
  - 记录请求体全文、响应体全文
  - 记录 token、password、refreshToken、消息正文
- 提供 `/healthz`，返回：
  ```json
  {"code":0,"message":"ok","data":{"status":"up"}}
  ```

```cpp
inline drogon::HttpResponsePtr makeJsonResponse(
    drogon::HttpStatusCode status,
    const nlohmann::json &body) {
    auto resp = drogon::HttpResponse::newHttpResponse();
    resp->setStatusCode(status);
    resp->setContentTypeCode(drogon::CT_APPLICATION_JSON);
    resp->setBody(body.dump());
    resp->addHeader("X-Content-Type-Options", "nosniff");
    resp->addHeader("X-Frame-Options", "DENY");
    resp->addHeader("Referrer-Policy", "no-referrer");
    return resp;
}

inline drogon::HttpResponsePtr makeSuccess(
    nlohmann::json data,
    std::string requestId = {}) {
    nlohmann::json body{
        {"code", 0},
        {"message", "ok"},
        {"data", std::move(data)}
    };
    if (!requestId.empty()) {
        body["request_id"] = std::move(requestId);
    }
    return makeJsonResponse(drogon::k200OK, body);
}

inline drogon::HttpResponsePtr makeError(const AppError &e) {
    // 错误体必须恰好三个字段
    nlohmann::json body{
        {"code", e.code()},
        {"field", e.field()},
        {"message", e.message()}
    };
    return makeJsonResponse(e.status(), body);
```

## 14.4 Repository 双查询 exactly-once 模板

```cpp
void UserRepository::countAndList(
    int page, int pageSize, const std::string &keyword, const std::string &status,
    std::function<void(std::variant<UserPage, AppError>)> cb) {

    struct State {
        std::atomic_int remaining{2};
        std::atomic_bool done{false};
        std::uint64_t total{0};
        std::vector<UserSummary> rows;
        std::function<void(std::variant<UserPage, AppError>)> cb;
    };
    auto state = std::make_shared<State>();
    state->cb = std::move(cb);

    auto finish = [state]() {
        if (state->remaining.fetch_sub(1) != 1) return;
        if (state->done.exchange(true)) return;
        state->cb(UserPage{state->total, std::move(state->rows)});
    };
    auto onError = [state](const drogon::orm::DrogonDbException &e) {
        if (state->done.exchange(true)) return;
        LOG_ERROR << "db error: " << e.base().what();
        state->cb(AppError::internal());
    };

    db_->execSqlAsync(countSql, [state, finish](const drogon::orm::Result &r) {
        try {
            state->total = r[0]["total"].as<std::uint64_t>();
            finish();
        } catch (...) {
            if (state->done.exchange(true)) return;
            state->cb(AppError::internal());
        }
    }, onError, /* 参数 */);

    db_->execSqlAsync(listSql, [state, finish](const drogon::orm::Result &r) {
        try {
            for (const auto &row : r) {
                state->rows.push_back(mapUserRow(row));
            }
            finish();
        } catch (...) {
            if (state->done.exchange(true)) return;
            state->cb(AppError::internal());
        }
    }, onError, /* 参数 */);
}
```

## 14.5 main.cc 初始化顺序

```cpp
int main(int argc, char **argv) {
    const std::string configPath = argc > 1 ? argv[1] : "./config.json";

    drogon::app().loadConfigFile(configPath);

    AppConfig cfg = AppConfig::fromDrogon();          // 校验并转换
    auto db = drogon::app().getDbClient("default");
    if (!db) {
        LOG_FATAL << "db client 'default' is not configured";
        return 1;
    }

    AppContext::instance().init(cfg, db);             // 构造 shared_ptr service/repository

    drogon::app().registerFilter(std::make_shared<AuthFilter>(cfg));
    drogon::app().registerFilter(std::make_shared<RbacFilter>());

    registerRequestIdAdvice();                        // filters/RequestIdAdvice
    registerCorsAdvice(cfg.corsOrigin);               // filters/CorsAdvice
    registerAccessLogAdvice();                        // filters/AccessLogAdvice

    // 自定义 404，返回统一错误 JSON
    // 可选：pre-sending 兜底 500

    drogon::app().run();
    return 0;
}
```
