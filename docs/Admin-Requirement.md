## 2. 背景与定位

### 2.1 项目背景

KC-CXIM（铖信）是一个面向学习与二次开发的全栈即时通讯项目，当前已具备：

- HTTP 注册 / 登录（bcrypt 密码哈希 + JWT HS256）；
- TCP 长连接（4 字节长度头 + JSON）与心跳、重复登录踢人；
- MariaDB 持久化：用户、好友、会话、成员游标、消息历史、离线消息；
- 单聊在线直推、离线落库补推、历史 keyset 分页、投递 / 已读回执；
- Windows 桌面端（duilib + 腾讯云 IM SDK）。

按照 `introduce.txt` 的划分，一套完整 IM 系统由“客户端、服务端、管理后台”三大主体构成。本需求文档聚焦**第三主体——管理后台（Web 控制台）**。

### 2.2 管理后台定位

管理后台是面向**运营与管理员**的 B/S 控制台，用于维护系统秩序、处理用户与内容、下发配置与公告、查看运行数据、追溯操作行为。

核心目标：

1. **可管**：用户、好友、群组、会话、消息、文件可按条件检索并处置。
2. **可控**：内容审核、敏感词、举报处理、消息撤回/删除形成闭环。
3. **可运营**：推送、公告、功能开关、限流参数在线调整。
4. **可观测**：仪表盘呈现在线数、消息量、用户活跃、趋势与告警。
5. **可追溯**：所有管理操作留痕，可审计、可导出、不可篡改。

### 2.3 与用户端的关系

- **账号体系分离**：管理端管理员账号与用户端 `users` 完全独立，使用独立表、独立 JWT 密钥/签发者、独立登录入口。
- **部署分离**：管理后台后端（Drogon）作为独立进程部署，不与 IM 长连接服务混部。
- **数据共享**：管理端与用户端共享 MariaDB 表结构，但使用独立数据库账号，生产环境建议“只读账号 + 写账号”分离。
- **域名分离**：独立域名、独立鉴权、独立权限模型。

## 3. 需求范围

### 3.1 本期范围（In Scope）

- 管理后台前端（Vue 3）与后端（Drogon）完整工程；
- 管理员登录、Token 刷新、登出、二次验证；
- RBAC 角色权限与管理员账号管理；
- 仪表盘与核心统计；
- 用户管理、好友关系管理；
- 群组管理（依赖后端群组能力，分期交付）；
- 会话与消息查询、消息治理（撤回/删除）；
- 内容审核（敏感词、举报、审核记录）；
- 推送管理（依赖推送服务，分期交付）；
- 系统配置与公告；
- 审计日志；
- 文件管理；
- 受控开放 API；
- 安全、部署、运维、测试与验收要求。

### 3.2 本期不包含（Out of Scope）

- IM 长连接协议本身的重构（TCP/WebSocket 选型见 `KC-CXIM-IMS-DESIGN.md`）；
- 用户客户端（桌面端 / 移动端 / Web 用户端）功能开发；
- 音视频媒体服务（WebRTC / SFU / TURN）本身；
- 移动端管理 App；
- 后端尚未实现能力的“强制落地”，但管理端需**预留入口与设计**。

### 3.3 能力依赖原则

现有自研后端仅完整支持“单聊 + 文本 + 离线 + 已读 + 历史”。因此管理后台功能分为两类：

- **A 类（可立即实现）**：仅依赖现有 6 张表与 HTTP/TCP 能力，列入 V1.0 MVP。
- **B 类（需后端先行）**：依赖群组、举报、敏感词、推送、设备、撤回等尚未实现的表/接口，管理端先完成设计与占位，待后端能力就绪后联调。

> 本文档中标注「依赖：BE-xxx」的需求均属于 B 类，交付时不得以“管理端已开发”视为可上线，需与后端里程碑对齐。

## 4. 总体架构与技术选型

### 4.1 逻辑架构

```text
┌──────────────────────────────┐
│  浏览器（Vue 3 管理端）        │
│  Nginx：静态资源 + 反向代理     │
└───────────────┬──────────────┘
                │ HTTPS / REST
┌───────────────▼──────────────┐
│  Admin Backend（Drogon 独立进程）│
│  鉴权 / RBAC / 业务 / 审计      │
└───────┬───────────────┬──────┘
        │               │
┌───────▼──────┐ ┌──────▼───────┐
│  MariaDB      │ │  Redis        │
│  用户/会话/消息 │ │ 缓存/限流/在线 │
└───────────────┘ └──────────────┘
        │
┌───────▼──────────────────────┐
│  IM 服务 / 推送服务 / 对象存储   │
│  （在线状态、撤回事件、推送、文件）│
└──────────────────────────────┘
```

### 4.2 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 管理端后端 | **Drogon**（C++17/20） | HTTP/1.1、WebSocket、ORM、插件、协程；独立进程部署 |
| 管理端前端 | **Vue 3 + TypeScript + Vite** | 组合式 API、类型安全 |
| 状态与路由 | Pinia + Vue Router | 全局状态、动态路由、路由守卫 |
| UI 组件 | Element Plus | 表格、表单、抽屉、弹窗 |
| 图表 | ECharts | 仪表盘趋势与占比 |
| HTTP | Axios | 拦截器、统一错误处理、重试 |
| 数据库 | MariaDB（沿用） | 共享现有 schema，新增管理端表 |
| 缓存/限流 | Redis（P1） | 会话、验证码、限流、在线状态 |
| 部署 | Nginx + Docker Compose | 静态托管 + 反向代理 + 一键编排 |
| 安全 | JWT + bcrypt/Argon2 + TOTP | 管理端独立密钥 |

> 选型理由见 `TODO-LIST.md` 4.2：管理端开发效率优先选择 Drogon；IM 长连接服务继续保留 Boost.Beast，不混部。

### 4.3 与 IM 服务的边界

- 管理端**不直接操作长连接**，不侵入 `SessionManager`。
- 需要在线数、强制下线、撤回广播等实时动作时，通过以下方式之一：
  1. IM 服务暴露内部 HTTP/RPC 管理接口；
  2. 通过 Redis 共享在线状态与事件通道；
  3. 管理端直接读库 + 由 IM 服务轮询/订阅变更（过渡方案）。
- 具体方式在《接口设计》阶段确定，本文档将其列为**待确认项**（见第 14 章）。

## 5. 角色与权限模型（RBAC）

### 5.1 角色定义

| 角色 | 标识 | 职责 |
| --- | --- | --- |
| 超级管理员 | `super_admin` | 全部权限；管理员账号与角色分配；系统配置；审计导出 |
| 系统管理员 | `sys_admin` | 用户/群组/消息治理/配置；不可管理超级管理员 |
| 运营 | `operator` | 推送、公告、统计、只读用户/群组；配置只读 |
| 审核员 | `moderator` | 内容审核、举报处理、消息撤回/删除、敏感词 |
| 客服 | `support` | 用户/好友/群组/消息只读，有限的用户协助操作 |
| 审计员 | `auditor` | 全模块只读 + 审计日志导出 |

### 5.2 权限矩阵

> 图例：`—` 无权限；`R` 只读；`RW` 读写；`A` 需审批/二次确认。

| 模块 | super_admin | sys_admin | operator | moderator | support | auditor |
| --- | --- | --- | --- | --- | --- | --- |
| 仪表盘 | R | R | R | R | R | R |
| 用户管理 | RW | RW | R | R | R（有限 RW） | R |
| 好友关系 | RW | RW | R | R | R | R |
| 群组管理 | RW | RW | R | R | R | R |
| 消息查询 | RW | RW | R | R | R | R |
| 消息治理（撤回/删除） | RW+A | RW+A | — | RW+A | — | R |
| 内容审核 | RW | RW | R | RW | R | R |
| 推送管理 | RW | RW | RW | — | — | R |
| 系统配置 | RW | RW | R | — | — | R |
| 管理员账号 | RW | R | — | — | — | R |
| 文件管理 | RW | RW | R | R | — | R |
| 审计日志 | R+导出 | R | — | — | — | R+导出 |
| 开放 API | RW | RW | R | — | — | R |

### 5.3 权限控制要求

- **接口级**：每个管理 API 必须声明所需权限码，后端强制校验，前端隐藏不作为安全边界。
- **菜单级**：前端根据权限动态生成菜单与路由。
- **按钮级**：新增/编辑/删除/封禁/撤回等按钮按权限显隐。
- **数据级**：敏感字段按角色脱敏；导出需二次确认或审批。
- **最小权限**：默认拒绝，角色按需赋权；禁止“超级管理员日常使用”。

## 6. 功能需求

> 编号规则：`ADM-<模块>-<序号>`；与 `TODO-LIST.md` 的 `ADM-BE-*` / `ADM-FE-*` 保持可追溯（见 6.15）。

### 6.1 认证与访问控制（ADM-AUTH）

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| ADM-AUTH-01 | 管理员登录 | 账号 + 密码；bcrypt/Argon2 校验；返回 access/refresh token | P0 |
| ADM-AUTH-02 | Token 刷新 | 短期 access + refresh；刷新时校验设备与会话 | P0 |
| ADM-AUTH-03 | 登出 | 吊销当前 refresh token；支持“全部设备登出” | P0 |
| ADM-AUTH-04 | 二次验证（2FA） | TOTP 优先，短信/邮箱验证码可选；高风险操作强制 | P1 |
| ADM-AUTH-05 | 登录安全 | IP 白名单、失败次数锁定、验证码、会话空闲超时 | P0 |
| ADM-AUTH-06 | 修改/重置密码 | 本人修改需旧密码；超管重置后强制下次登录修改 | P0 |
| ADM-AUTH-07 | 管理员账号管理 | 新增、禁用、删除、角色分配、重置密码（仅超管） | P0 |
| ADM-AUTH-08 | 独立鉴权域 | 管理端 JWT 与用户端隔离，密钥、issuer、过期策略独立 | P0 |

**验收要点**：

- 连续失败 N 次（默认 5）锁定 M 分钟（默认 15），并记录审计；
- access token 过期后接口返回 `40101`，前端自动尝试刷新；
- 禁用管理员后，其现有 token 立即失效（依赖会话版本号/黑名单）。

### 6.2 仪表盘与统计（ADM-DASH）

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| ADM-DASH-01 | 核心指标卡 | 当前在线数、今日消息量、今日活跃用户、新增用户、群组总数 | P0 |
| ADM-DASH-02 | 趋势图 | 近 7/30 天消息量、DAU/MAU、新增用户、离线积压 | P0 |
| ADM-DASH-03 | 分布图 | 消息类型占比、会话类型占比、平台/设备分布（有数据时） | P1 |
| ADM-DASH-04 | 实时告警 | 错误率、DB 连接、推送失败率、离线队列积压阈值告警 | P1 |
| ADM-DASH-05 | 数据口径说明 | 指标定义、统计周期、缓存时间在页面可查 | P1 |

**依赖与说明**：

- 消息量、用户量、群量可直接统计 MariaDB；
- **在线数**当前来自 IM 进程内 `SessionManager`，管理端无法直接读取，需后端提供接口或 Redis 在线状态（`依赖：BE-SCALE-01`）；
- 统计查询避免全表扫描，必要时使用汇总表/定时任务。

### 6.6 会话与消息查询（ADM-MSG）

| 编号 | 需求 | 说明 | 优先级 |
| --- | --- | --- | --- |
| ADM-MSG-01 | 消息检索 | 按会话、发送者、接收者、时间范围、类型、关键词检索 | P0 |
| ADM-MSG-02 | 会话视图 | 按 `conversation_id` 查看上下文，keyset 分页 | P0 |
| ADM-MSG-03 | 消息详情 | 展示 msg_id、seq、发送者、类型、内容、时间、会话 | P0 |
| ADM-MSG-04 | 关联跳转 | 从用户详情跳到其会话/消息 | P1 |
| ADM-MSG-05 | 导出 | 脱敏导出，需审批，记录审计 | P1 |
| ADM-MSG-06 | 只读保护 | 默认只读；写操作仅限“消息治理”模块 | P0 |

**分页与性能**：

- 采用 keyset 分页：`WHERE conversation_id = ? AND seq < ? ORDER BY seq DESC LIMIT ?`；

**消息类型与展示**（来源：`TODO-LIST.md` 3.5.1、`readme.md` 协议表）：

| 值 | 类型 | 内容字段建议 | 管理端展示 |
| --- | --- | --- | --- |

## 8. API 设计规范

### 8.1 通用约定

- 基础路径：`/admin/api`；
- 鉴权：`Authorization: Bearer <access_token>`；
- 编码：`application/json; charset=utf-8`；
- 时间：ISO 8601 或毫秒时间戳，统一约定；
- 分页：`page`、`page_size`（默认 20，最大 100）；消息/日志支持 `cursor`；
- 幂等：写操作支持 `Idempotency-Key`（可选）；
- 追踪：请求/响应带 `request_id`，贯穿日志与审计。

### 8.2 统一响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "request_id": "b1f2c3d4"
}
```

### 8.3 错误码

| code | HTTP | 含义 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 40001 | 400 | 参数错误 |
| 40100 | 401 | 未认证 |
| 40101 | 401 | access token 过期 |
| 40102 | 401 | 凭据无效/已吊销 |
| 40300 | 403 | 无权限 |
| 40400 | 404 | 资源不存在 |
| 40900 | 409 | 状态冲突（如重复封禁） |
| 42900 | 429 | 触发限流 |
| 50000 | 500 | 服务内部错误 |
| 50300 | 503 | 依赖不可用（DB/Redis/推送） |

| ADM-NFR-02 | 并发 | 支持 ≥ 50 个管理员同时在线；日常操作无阻塞 |
| ADM-NFR-03 | 可用性 | 管理端可用性 ≥ 99.9%；依赖故障时给出明确错误而非白屏 |
| ADM-NFR-04 | 安全 | 全站 HTTPS；JWT 安全存储；CSRF/CSP/X-Frame-Options；参数化查询 |
| ADM-NFR-05 | 审计 | 所有写操作可追溯；审计不可被普通管理员篡改 |
| ADM-NFR-06 | 隐私 | 敏感字段脱敏展示；导出需授权；遵守数据保留与删除策略 |
| ADM-NFR-07 | 可观测 | 结构化日志、request_id、健康检查、关键指标、告警 |
| ADM-NFR-08 | 兼容 | 浏览器兼容；API 版本化与向后兼容 |
| ADM-NFR-09 | 可维护 | 配置外置；模块化；OpenAPI 文档；前后端分离 |
| ADM-NFR-10 | 数据保留 | 审计 ≥ 180 天；消息保留周期按产品确认（参考 schema 180 天示例） |

## 11. 安全需求

| 编号 | 要求 |
| --- | --- |
| ADM-SEC-01 | 独立域名 + HTTPS + WAF/限流；管理端不暴露在公网无防护环境 |
| ADM-SEC-02 | Token 放 HttpOnly Cookie 或内存 + 短期有效，降低 XSS 窃取风险 |
| ADM-SEC-03 | Cookie 模式启用 CSRF 防护；配置 CSP、X-Frame-Options、Referrer-Policy |
| ADM-SEC-04 | SQL 注入防护：参数化查询、ORM 白名单、禁止拼接 |
| ADM-SEC-05 | 操作审计与不可抵赖：记录操作人、IP、UA、前后值 |
| ADM-SEC-06 | 敏感数据脱敏展示；导出审批；日志脱敏，禁止打印密码/token/消息正文 |
| ADM-SEC-07 | 管理端与用户端鉴权隔离；不同密钥、不同 issuer、不同表 |
| ADM-SEC-08 | 登录防爆破：失败锁定、验证码、IP 白名单、异常登录告警 |
| ADM-SEC-09 | 依赖安全：定期扫描漏洞；禁止引入来源不明依赖 |
| ADM-SEC-10 | 最小权限数据库账号；生产环境禁用高危 SQL 与批量物理删除 |

## 13. 里程碑与交付计划

> 与 `TODO-LIST.md` 第 2 章、第 9 章对齐；管理后台整体位于“群聊与富媒体”之后，但认证、用户、消息查询可提前并行。

| 阶段 | 范围 | 交付物 | 前置条件 |
| --- | --- | --- | --- |
| M0 基础框架 | 工程脚手架、登录、RBAC、统一响应、审计骨架 | 可登录的空壳后台 | 无 |
| M1 MVP（A 类） | 仪表盘基础、用户管理、好友关系、消息查询、审计日志、管理员账号 | 可运营的最小后台 | 现有 6 表 + HTTP/TCP |
| M2 治理与群组 | 消息治理、内容审核、群组管理、系统配置 | 审核与群管闭环 | `BE-GROUP-*`、`BE-MSG-06`、`BE-RT-06` |
| M3 运营增强 | 推送管理、文件管理、高级统计、开放 API | 完整运营工具 | `BE-RT-11`、`BE-OSS-*`、`BE-DB-*` |
| M4 成熟化 | 2FA、SSO（可选）、多租户（按需）、容量优化 | 生产级后台 | 安全与容量评审 |

**MVP 建议先做**：登录 + RBAC + 用户封禁 + 消息检索 + 撤回 + 审计。这五项构成“能管住人、能查到消息、能处置内容、能追责”的最小闭环。

## 14. 验收标准

### 14.1 功能验收

- [ ] 管理员可登录、刷新 token、登出；错误密码与锁定策略生效。
- [ ] RBAC 生效：低权限角色无法访问高权限接口与菜单。
- [ ] 用户列表、详情、封禁/解禁可用；封禁后用户无法登录/发消息（依赖后端）。
- [ ] 好友关系可查询、解除，双向一致。
- [ ] 消息可按会话/用户/时间/类型检索，分页正确，未知类型可降级展示。
- [ ] 消息撤回/删除有权限校验、二次确认与审计记录。
- [ ] 举报处理闭环：受理 → 处置 → 记录可查。
- [ ] 敏感词增删改查生效（依赖后端过滤）。
- [ ] 仪表盘指标与数据库统计一致，口径可查。
- [ ] 审计日志完整、可筛选、可导出，普通角色不可篡改。
- [ ] 群组管理各操作可用（依赖后端群组能力）。
- [ ] 推送模板、人群、定时、记录可用（依赖推送服务）。

### 14.2 安全验收

- [ ] 全站 HTTPS；CSP、X-Frame-Options、CSRF 生效。
- [ ] SQL 注入、XSS、越权访问测试通过。
- [ ] 敏感字段脱敏；导出需授权并留痕。
- [ ] 管理端与用户端 token 不可互换使用。
- [ ] 登录防爆破与异常告警有效。

### 14.3 性能与稳定性验收

- [ ] 常规接口 P95 ≤ 300ms（基线数据量）。
- [ ] 50 并发管理员操作无错误、无明显抖动。
- [ ] 大数据量消息表分页无深分页性能问题。
- [ ] 依赖故障（DB/Redis）时错误可读、可恢复。

### 14.4 工程验收

- [ ] 前后端构建通过；单测与静态检查通过。
- [ ] OpenAPI 文档完整，接口与实现一致。
- [ ] Docker Compose 一键启动；健康检查通过。
- [ ] 部署文档与运维手册齐全。

## 15. 风险与依赖

| 风险/依赖 | 影响 | 应对 |
| --- | --- | --- |
| 后端群组/举报/推送/设备/撤回能力未实现 | 管理端相关模块无法真正上线 | 设计先行、分期交付；明确 B 类需求依赖 |
| 在线状态为进程内内存 | 仪表盘在线数、强制下线无法实现 | 后端外置 Redis 或提供内部接口（`BE-SCALE-01`） |
| 管理端与 IM 共享数据库 | 并发、权限、误操作风险 | 独立 DB 账号、读写分离、参数化、审计 |
| 消息表持续增长 | 检索与统计变慢 | keyset 分页、索引、归档/分区，必要时搜索服务 |
| 管理端账号被攻破 | 数据泄露、越权操作 | 2FA、IP 白名单、最小权限、审计、告警 |
| 敏感内容与隐私合规 | 法律与合规风险 | 脱敏、授权访问、保留/删除策略、操作留痕 |
| 协议/表结构演进 | 管理端与后端不一致 | 契约先行、OpenAPI、版本化、联调门禁 |
| 前端权限仅隐藏 | 误以为安全 | 后端强制校验，前端仅做体验 |

## 16. 待确认问题（Open Questions）

1. **管理端与 IM 服务的集成方式**：直接共享数据库，还是由 IM 服务提供内部管理 API？强制下线、撤回广播、在线状态如何获取？
2. **MFA 范围**：是否所有管理员强制 2FA，还是仅高风险操作触发？
3. **登录方式**：仅账号密码，还是需要 SSO / LDAP / 企业微信？
4. **消息内容可见性**：管理员是否可查看完整消息正文？是否需要审批或水印？隐私边界如何界定？
5. **消息删除策略**：软删除（墓碑）还是物理删除？保留期限与合规要求？
6. **群组能力时间表**：`groups` 等表与接口何时就绪？管理端是否可以先做只读占位？
7. **推送渠道**：自建推送还是对接 APNs/FCM/厂商通道？管理端是否需要模板审核？
8. **统计口径**：DAU/MAU、在线数、消息量的精确定义与刷新频率？
9. **部署形态**：是否与 IM 服务同机部署？是否需要多实例与灰度？
10. **数据导出与合规**：导出审批流、脱敏规则、数据保留周期由谁制定？
11. **国际化**：是否需要中英双语？首发语言？
12. **管理端域名与网络**：是否仅内网访问 / 是否需要 VPN / IP 白名单范围？

| 术语 | 含义 |
| --- | --- |
| RBAC | 基于角色的访问控制 |
