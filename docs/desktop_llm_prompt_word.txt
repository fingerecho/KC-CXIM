【提示词10：TCP 群消息收发、群历史、回执（会话模型扩展为 单聊+群聊 双形态）】
基于现有 TcpClient 实现群消息链路（对照 readme §6.13 与 session.cpp 的 do_send_group/do_history_group）：
1) 会话唯一键扩展：用 (is_group, peerOrGroupId) 作为本地会话 key——单聊 key=C:uid、群聊 key=G:groupId；
   会话对象记录 conversation_id（服务端 SendAck/消息里带回）。本地消息去重一律用 (conversation_id, seq)。
2) 发群消息：type=1（图片 type=2），to=groupId，is_group=true，msg_id=本地自增临时号，content=文本；
   服务端回 SendAck=113（is_group=true，带 conversation_id/seq/ts；content="sent"/"duplicate"），
   气泡状态机与单聊一致（发送中→已发送/失败）。
3) 接收群消息：下行 type=1/2 且 is_group=true 时，to=groupId（不是接收者自己），from=发送者 userId；
   渲染到对应群会话（气泡上方显示发送者昵称，从群成员表取，取不到先显示 userId），
   并照单聊规则回 112 回执（"delivered"=已投递、content 空=已读，带 conversation_id+seq）。
   注意：登录时服务端会补推离线群消息（同样 is_group=true），并且“在线收到过但未 ACK”的消息重连时会再次下发，
   必须按 (conversation_id, seq) 去重，不重复渲染、不重复计数。
4) 群历史：打开群会话发 type=110 {to=groupId, is_group=true, seq=0(=before_seq), content="20"}；
   响应 111 的 content 是 JSON 数组文本（元素含 msg_id/conversation_id/seq/from/type/ts/content/is_group），
   二次解析、按 seq 升序渲染、最新在底部、上拉翻页用当前最小 seq；非成员/已解散的群服务端直接回 Error(102)。
5) 被移出/退群/解散时：立即停止该群的收发展示，会话行变灰或移除（提示“你已不在该群”），
   不再渲染该群后续消息；服务端是唯一事实源，客户端不要自行推断成员状态。

【提示词11：群事件处理（type=140~144）与本地群缓存一致性】
